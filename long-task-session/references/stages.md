# 六阶段细化

每个阶段的"退出条件"都必须是**可执行检查**，不允许用"感觉差不多了"。

---

## S0 对账（Reconcile）

**目的**：把新上下文接到既有事实上，而不是从头推理。

**输入**：上一轮会话目录（`state.json`、`NEXT_PLAN.md`、`SESSION_LOG.md` 末尾）、产物文件。

**动作**（按顺序，全部执行）：

```bash
python3 scripts/sessionctl.py list --root ./sessions      # 有哪些会话
python3 scripts/sessionctl.py reconcile --root ./sessions  # 最新一个的摘要
python3 scripts/sessionctl.py verify --session <dir>       # 产物哈希是否还对得上
python3 scripts/sessionctl.py resume --session <dir>       # 下一条命令是什么
```

人工补三项外部状态（脚本管不到）：进程/服务是否在跑、资源是否被占（GPU/端口/磁盘）、输入数据版本。

**产出**：在新会话的 `SESSION_LOG.md` 写第一条记录，内容包含"对账结论 + 与上轮日志的差异"。

**退出条件**：`reconcile` 有输出且 `verify` 返回 0（或把不一致项逐条写进日志并说明处置）。

**常见错误**：只看日志时间戳就推断进度（时钟可能偏）；把"文件存在"当成"内容正确"（要验哈希）。

---

## S1 定界与量噪（Frame）

**目的**：把"要改什么"说清楚，并先知道**这个指标有多不听话**。

**动作**：

1. 写清问题的一句话陈述 + 当前证据（谁测的、口径、样本量）。
2. **口径复现**：用现在的工具复算一个历史数字。复现不出来 → 先修口径，不要往下走。
3. **噪声带**：同一输入重复 ≥3 次（或按 `references/metrics.md` 的算法），记录 sd 与极差。
4. 无历史基准时（首次任务）：做一次**小样基线**，写明 n、参数、工具版本，此后对比以它为准。

**产出**：`SESSION_PLAN.md` 的 `## 2. 当前证据` 与 `## 5. 预注册判定` 两节。

**退出条件**：复现值落在噪声带内；阈值已按 `≥2×SE` 设定。

**常见错误**：拿不同口径的历史分数直接比；用单次测量当基线（可能正好落在噪声的极端）。

---

## S2 方案与筛选（Options）

**目的**：避免"想到一个就干"，也避免"重复讨论已否决的路线"。

**动作**：

1. 列 2–4 个方案，每个写：做法、预期收益、成本、失败时的代价。
2. 逐个用 `references/patterns.md` 的模式检查；被否的必须写清"被哪条模式否掉"。
3. 把结论写进 `## 3. 候选方案与裁决` 与 `## 8. 决策记录（DECISIONS）`。

**退出条件**：每个被否方案都有一行证据；保留方案 ≤2 个（更多的排到下一轮）。

**常见错误**：只留一个方案（没有对照）；把"上次试过不行"当结论却不写原因（下一位读者无法判断是否适用）。

---

## S3 夯实（Harden）

**目的**：把计划写成"换个人也能执行"的形态。

**七件硬内容**（缺一不可，`status` 会检查）：

1. 问题陈述（要做成什么）
2. 当前证据（含口径与样本量）
3. 候选方案与裁决（含被否理由）
4. **单变量表**（参考版本 vs 本次，只能有一个"是"）
5. **预注册判定**（指标 / 阈值 / 判定规则 / 噪声带 / 不达标动作）
6. 成本与资源（时长、配额、GPU、磁盘）
7. **回退点**（git 标签或备份路径，写清怎么回）

附加必需：`## 8. 决策记录（DECISIONS）`（只追加）。

**退出条件**：`sessionctl status` 检查项 1 通过。

**常见错误**：单变量表里出现两个"是"；阈值写成"尽量提高"；回退点写"重新训练"（那不叫回退点）。

---

## S4 执行（Run）

**目的**：把计划跑成产物，且**任何时刻中断都能接上**。

**动作**：

1. 用 `templates/launcher.sh` 起长任务：幂等、前置自检、日志固定路径。
2. 用 `templates/watcher.sh` 盯：心跳写 `logs/heartbeat.log`，退出条件绑真实终态标记。
3. 每个里程碑（训练完成、批量完成、评估完成、备份完成）执行 `sessionctl ckpt`。
4. **每 40 分钟至少写一条记录**（含 `sessionctl note` 与心跳），不允许"等它跑完再一次性写"。

**退出条件**：终态标记出现 + `ckpt` 登记了产物 + `state.json` 的 run 状态为 done。

**常见错误**：用副作用字符串判完成；watcher 绑死当前对话；只写"已启动"不写进度。

---

## S5 验收与沉淀（Verify & Distill）

**目的**：给出可复核的结论，并把下一轮的成本算清楚。

**动作**：

1. 填 `SESSION_LOG.md` 的三张表：`## 验收：通过`、`## 验收：不通过`、`## 验收：中性`（没有内容写"无"）。
2. 每条红线都要有判定（`state.json.gates.<name>.verdict` 非空）——`close` 会逐行检查。
3. 写 `## Gap 归因`：差距落在哪个变量上；哪些是噪声；哪些是口径问题。
4. 写 `NEXT_PLAN.md`：已完成 / 未完成 / 未解问题 / 下阶段候选（带成本与前置条件）/ **不要做什么**。
5. `sessionctl close --backup` 归档，确认备份路径写回 `ARTIFACTS.md` 与 `NEXT_PLAN.md`。

**退出条件**：`sessionctl status` 四项全过；`close` 返回 0。

**常见错误**：只写"通过/不通过"不写中性（噪声内的结果必须显式记中性）；把结论写成叙事而不给判定表。
