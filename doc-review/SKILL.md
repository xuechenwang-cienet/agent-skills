# doc-review：双 Agent 文档评审

对正式文档做评审与修订时，不要"通读一遍给意见"。本 skill 提供的是**流程、角色职责与评审标准**：快照 → 初审 → 独立复核 → 人工决策 → 受控修复 → diff 审计，每步有闸门、有工件、有证据。它不针对任何特定文档；文档族差异通过配置（`templates/review-config.md`）注入，结构特定的检查由评审者按标准用通用工具执行。

## 核心理念

1. **对抗独立。** 评审者不继承作者的假设：从文件与原件取证，不听转述；评审者与作者尽量用不同模型家族。
2. **证据优先。** 无证据不成条；每条发现给位置、实测、期望、复现命令；拿不到证据写"待确认 + 需要执行的检查"，不写"疑似"。
3. **决策留痕。** 治理判断（标识、基线、语言、法规）由人决定并落盘；只存在于对话里的决策，下轮会被当作错误重提。
4. **diff 审计兜底。** 有"前后快照 + 接受清单"，编辑者是谁不重要；没有 diff 审计，让谁改都不安全。

## 分级

| 档 | 场景 | 内容 |
|---|---|---|
| L1 | 非交付的小改动 | 单角色评审 + 机械检查 + 发现清单 |
| L2 | 一般交付文档 | 双审 + 人工决策 + 受控修复 + diff 审计 |
| L3 | 基线/受控/客户可见文档、引用外部标准 | L2 + 声明登记表全量 + 外部来源核验 + 决策记录 + 评审者校准 |

判据：会被外部审计或客户检查？引用带版本号的标准？需要签字基线化？任一"是"→ L3。

## 角色与职责

每个角色一份职责书。启动任何 sub-agent 前，把对应职责书放进任务书（见 `references/prompts.md`）。

**协调者（主 agent）**
- 使命：对评审轮次的正确性与闭环负责。
- 职责：建立基线快照；写任务书（只含路径与要求，不贴全文）；汇总发现与决策点；以"选项+默认建议+代价"的形式向决策者提问并落盘；维护接受清单；**亲自复核 P0/P1 的关键证据**；汇报最终结论。
- 权限：调度各角色、执行或委托修复、使用通用工具。
- 禁止：代替决策者做治理判断；跳过闸门；把全文转述进 sub-agent 任务书。
- 产出：任务书、接受清单、最终汇报。

**初审评审者（独立 sub-agent）**
- 使命：独立、以证据为限地发现问题。
- 职责：按 12 维标准逐维度检查（顺序：机械→语义→治理）；填写声明登记表裁定列；每条发现八字段齐全（含复现命令）；治理类问题转成决策点。
- 权限：只读被审文件与参照材料；可运行通用工具与自建的临时检查命令。
- 禁止：修改被审文件；无证据断言；信任任何摘要、转述或自己上一轮的结论。
- 产出：`01-findings.md`、`claims.csv`。

**复核评估者（独立 sub-agent，与初审不同模型家族）**
- 使命：对抗性验证初审。
- 职责：逐条**独立复现**初审的证据；标注 接受/拒绝/修改 + 理由；扫初审的遗漏（重点：上轮新增内容与机械层）。
- 权限：只读。
- 禁止：重写初审结论（只标注，保留 finding ID 与原文）；与初审共享上下文。
- 产出：`02-assessment.md`。

**决策者（人）**
- 使命：治理判断的唯一权威。
- 职责：回答决策问题（每题已给出选项、默认建议与代价）。
- 权限：决定文档标识、基线规则、语言策略、法规适用、强度取舍。
- 约束：未落盘的决定视为未做。
- 产出：`03-decisions.md`。

**修复执行者（sub-agent 或协调者）**
- 使命：严格照单修改。
- 职责：逐条执行编辑规格；**规格与实际不符即停止该条并报告**；执行后跑该条的验证命令；结构性操作（插行/移动/删除）必须复查联动项（合并区域、数据验证、条件格式、公式范围）；写执行日志。
- 权限：修改被审文件，仅限已接受项。
- 禁止：自行发挥替代方案；越出接受清单。
- 产出：`04-fix-summary.md`（fix→finding 映射、执行记录、验证结果、显式拒绝项）。

**终审审计者（独立 sub-agent，与初审不同家族）**
- 使命：证明修复如实、完整、无回归。
- 职责：diff 逐块分类（应改已改 / 应改未改 / 回归 / 文本外变更）；机械复测（结构断言、计数、范围、链接、残留）；核对声明同步（摘要/决策记录/修订历史 vs 实物）。
- 权限：只读。
- 禁止：直接修复（发现问题回阶段 4，计入轮次上限）。
- 产出：`05-post-fix-review.md`。

**模型分工原则**（具体配置写进 review-config，经用户确认后生效）：评审类角色选与作者不同家族的强推理模型；执行类角色选工具调用稳定的模型；选型标准是"工具可靠性 > 榜单分数"——评审者要跑命令取证，工具不稳的强模型会把"取不到证据"变成"编造证据"。

## 流程：六阶段五闸门

| 阶段 | 执行者 | 产出 | 闸门（可用 `scripts/gate_artifacts.py` 校验） |
|---|---|---|---|
| 0 基线 | 协调者+脚本 | 快照 + manifest（SHA256）+ 结构与内容盘点 | 盘点无缺项 |
| 1 初审 | 初审评审者（只读） | 01-findings + claims.csv | 每条发现有证据与复现命令；每条声明有裁定 |
| 2 复核 | 复核评估者（只读） | 02-assessment | 每条 finding 有状态（接受/拒绝/修改） |
| 3 决策 | 决策者+协调者 | 03-decisions | 所有治理问题已由人回答 |
| 4 修复 | 修复执行者 | 04-fix-summary | 只修已接受项且 1:1 映射；验证通过；交付前完成残留清理 |
| 5 终审 | 终审审计者（只读） | 05-post-fix-review | 0 未解释差异、0 回归 |

两轮封顶：终审发现回归 → 回阶段 4，最多两轮；仍有问题记入遗留清单交人处理。L1 简化为阶段 0/1/4。

## 评审标准（12 维）

评审按标准执行，**顺序固定：机械 → 语义 → 治理**（顺序错了，语义结论要因机械层问题返工）。每维的判定方法、证据形式、通过标准见 `references/dimensions.md`。

| # | 维度 | 判定者 | 一句话标准 |
|---|---|---|---|
| 1 | 结构完整性 | 评审者+工具 | 编号连续；表格无被空行切断；单元格引用与所在行一致（格式规范）；合并/校验/公式范围覆盖全部数据 |
| 2 | 声明与实物一致 | 评审者+工具 | 文档及其摘要中的计数/标识/版本/日期/链接/存在性陈述与实测一致 |
| 3 | 引用存在性 | 工具 | 引用指向存在的章节/文档；链接可达（区分真失效与反爬拦截） |
| 4 | 引用支撑性 | 评审者 | 被引条款的原文确实支撑该要求（拒绝相邻原则顶替） |
| 5 | 外部文档核验 | 评审者+人 | 以文档自身元数据为准（不是文件名）；现行性由人确认 |
| 6 | 事实与时效 | 评审者 | 标准版本/工具状态/编号/日期对照官方源；模型记忆不得单独作依据 |
| 7 | 内部一致性 | 评审者+工具 | 同一标识在封面/历史/页脚/交叉引用/姊妹文件同值同写 |
| 8 | 覆盖完整性 | 评审者+工具 | 双向矩阵无单向缺口（章节↔条目↔活动↔标准条款） |
| 9 | 语义质量 | 评审者 | 每条要求可验证、适用、有依据、成本匹配；判断必须引参照 |
| 10 | 治理与合规 | **人** | 标识/基线/审批/语言/法规 → 决策记录 |
| 11 | 交付完整性 | 工具 | validate 通过、无占位符、无工具残留属性 |
| 12 | 回归与差异 | 评审者+工具 | 修复前后 diff 逐块对照接受清单，0 未解释差异 |

## 工件与目录

```
review/round-N/
├── manifest.json / inventory/   阶段 0：快照哈希与盘点
├── claims.csv                   声明登记表
├── 01-findings.md … 05-post-fix-review.md   五份工件（模板见 templates/）
└── snapshot/                    修复前快照（终审 diff 基线）
review-config.md                 文档族配置（被审对象、参照系、模型表、脚本参数）——skill 通用性的出口
```

字段定义见 `references/schemas.md`（声明登记表 / 发现八字段 / 编辑规格 / ≤10 行返回格式 / manifest）。

## 硬规则（八条）

1. 无证据不成条（位置/实测/期望/复现缺一即退回）。
2. 评审者只读；产出只写 `review/round-N/`。
3. 复核者标注不重写（保 finding ID）。
4. 修复 1:1 映射到已接受的 finding；未接受的显式拒绝并写理由；规格不符即停。
5. 治理决策必须问人，生成决策问题而非代答。
6. 引用内部文档以文档自身元数据为准，文件名只作线索。
7. 文档编辑工具可能在保存时写入自身元数据（含只读访问触发的驻留刷新）——交付前最后一步做 zip 级残留清理，此后不再用该工具触碰交付文件。
8. 两轮封顶；P0/P1 清零即止。

## 上下文经济

文件交接（任务书只含路径与要求）；sub-agent 返回"产出路径 + ≤10 行摘要"；机械工作交给脚本；协调者只读 P0/P1 与决策点。**反模式**：为省上下文把协调者变成只转发不判断的调度器——P0/P1 关键证据必须亲自复核，否则多 agent 只会稀释责任。

## 评审者校准

换模型/首次使用/改提示词后，先用已知答案的小用例验证评审流程本身（假声明识别、404 与反爬区分、元数据陷阱、相邻原则顶替），通过再放全量。用例见 `calibration/`。

## 失败模式与先例

19 条真实失败模式（含教训与判定方法）见 `references/casebook.md`，评审者遇到拿不准的判断先查先例。

## 通用工具（附录）

只提供跨文档通用的机械能力；**不预置针对特定文档结构的检查**——结构语义判断（什么算数据行、行连续性含义等）由评审者按 12 维标准执行。

| 工具 | 能力（均为通用） |
|---|---|
| `check_links.py` | 链接逐个请求：状态码、重定向链、404 与反爬拦截区分、UA 复测 |
| `diff_snapshot.py snap/diff` | 快照+SHA256 清单；两快照差异（文本级 diff、文本外变更单列） |
| `inventory_docx.sh` | docx 结构与内容导出（outline/stats/issues/域/属性/页脚） |
| `inventory_xlsx.py` | xlsx 结构与单元格导出（纯只读）：工作表/合并/校验/条件格式/公式/隐藏行 + 格式规范检查（单元格-行引用一致性、#REF!） |
| `claim_scan.py` | 声明登记表初稿（计数/标识/版本/日期/链接抽取；语言相关，按需调整模式） |
| `integrity_gate.sh` | validate + 占位符扫描 + 工具残留检查 |
| `gate_artifacts.py` | 阶段闸门可执行化：工件齐全/声明有裁定/发现八字段/修复映射/终审结论 |
| `final_clean.py` | zip 级清除编辑工具写入的自定义属性（幂等，交付前最后一步） |

对特定文档需要专门检查时（如本案例库中的行连续性、范围联动），正确做法：评审者在评审中用 officecli/python 自建一次性命令取证，验证有效后作为**该文档族的经验**记入 review-config 或案例库——而不是把判断逻辑固化进通用 skill。

## 快速开始

```bash
# 阶段 0：基线
<SKILL>/scripts/diff_snapshot.py snap --out <round>/snapshot <被审文件...>
<SKILL>/scripts/inventory_docx.sh <docx> <round>/inventory
<SKILL>/scripts/inventory_xlsx.py <xlsx> <round>/inventory
# 阶段 1：声明初稿 → 初审 agent 补裁定
officecli view <docx> text > /tmp/opencode/<name>.txt
<SKILL>/scripts/claim_scan.py /tmp/opencode/<name>.txt <修改摘要> > <round>/claims.csv
# 阶段 1-2：按 references/prompts.md 启动只读评审/复核 sub-agent
# 阶段 3：决策点问人 → 03-decisions.md
# 阶段 4：编辑规格 → 执行 → integrity_gate → final_clean
# 阶段 5：diff 审计 → 05-post-fix-review.md
<SKILL>/scripts/gate_artifacts.py <round> --stage review   # 每阶段收口（review/fix/final）
```
