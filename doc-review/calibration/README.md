# 评审者校准（换模型 / 首次使用 / 改提示词后必跑）

目的：验证**评审流程本身**有效，而不是只验证文档。新模型第一次当 reviewer、或换了提示词/档位，先跑这 4 个用例（约 2 分钟）；校准不过，不放全量。

## 用例 1：假声明识别（自包含）

- 输入: `fixtures/claims.md`
- 任务: 按声明核验流程检查其中每条陈述
- 通过: 4 条预埋错误全部找到，且各附实测证据；不把真声明误报为假（GROUND-TRUTH.md 有答案，校准前不给评审者）

## 用例 2：链接判定（联网）

- 输入: `fixtures/links.txt`（3 条 URL）
- 任务: 逐条判定有效性
- 通过: 200 / 404（含重定向链识别）/ 反爬拦截 三类判定各正确一条；把 403 一律当"失效"判为不通过

## 用例 3：内部文档元数据陷阱（用真实内部文档）

- 输入: 任一份公司内部文档（要求其封面 Document ID 与文件名写法不一致）
- 任务: 核对引用编号应采用哪个写法
- 通过: 以**文档自身封面编号**为准并给出证据；跟文件名走的判为不通过

## 用例 4：相邻原则顶替（用真实检查单/指南对）

- 输入: 一对"检查项 ↔ 指南章节"引用，其中检查项要求的内容在被引章节**并未出现**（只在相邻章节或仅有主题相关性）
- 任务: 判定引用支撑性
- 通过: 判为弱映射/不支撑，并引用被引章节原文证明；仅凭主题相关性判"支撑"的为不通过

## 评分与处置

- 4/4 通过 → 放行全量评审
- 任何一项失败 → 先修提示词/换档位/换模型，重跑校准；**禁止**带病进入正式轮次
- 校准记录写入当轮 `review/round-N/`（用例、结果、结论），复用时免重跑

## 运行示例

```bash
python3 ../scripts/claim_scan.py fixtures/claims.md
python3 ../scripts/check_links.py --from-file fixtures/links.txt
# 评审者对 fixtures/claims.md 的 4 条预埋错误给出实测证据后再对照 GROUND-TRUTH.md
```
