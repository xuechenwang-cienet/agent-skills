# sub-agent 提示词契约

协调者启动 sub-agent 时套用以下模板（替换 `<...>` 占位符）。四个契约共同点：**只读被审文件、产出写进 review/round-N/、返回只给路径 + ≤10 行摘要**。

## 1. 初审 reviewer（阶段 1）

```
任务：对以下文档做独立评审，产出审核意见。

对象（只读，禁止修改）：
<被审文件路径列表>
参照材料：
<原件/备份/关联文档路径；引用标准清单>

先做：
1. 读 <skill路径>/references/dimensions.md，按 12 维逐项检查（顺序：机械→语义→治理）。
2. 跑 <skill路径>/scripts/ 下的盘点与链接脚本，把输出存到 <round目录>/inventory/。
3. 逐条核验 claims.csv 初稿并补全裁定列。

产出（写入 <round目录>/01-findings.md）：
- 每条发现按 references/schemas.md 的 finding 结构（八字段齐全）
- 声明登记表更新为 <round目录>/claims.csv
- 治理类问题单独汇总成"待决策清单"（选项 + 默认建议 + 代价）

硬规则：
- 无证据不成条：位置、实测、期望、复现命令缺一不写
- 外部断言给状态码或官方源 URL；内部文档以自身封面元数据为准
- 拿不到证据写"待确认 + 需要执行的检查"，不写"疑似"
- 你是独立评审者：不信任任何摘要与转述，一切以实测为准

返回：产出文件路径 + ≤10 行摘要（P0/P1 计数、关键结论、待决策问题数）。
```

模型：与作者不同家族的强推理模型（用户配置后传 `model` 参数，如 `providerID/modelID#high`）。

## 2. 复核 assessor（阶段 2）

```
任务：评估另一位评审者的审核意见，标注每条的处置状态。你不重写他的结论。

输入（只读）：
<round目录>/01-findings.md、claims.csv、inventory/
被审文件（只读，用于验证对方证据）

对每条发现：
1. 独立复现其证据命令——证据复现不了的，标 rejected（理由：不可复现）
2. 用自己的方法再查一遍该位置——发现对方结论错的，标 modified 并给出修正
3. 成立的标 accepted
4. 检查对方遗漏：重点扫"修复轮新增内容"与"机械层"（结构/计数/范围），补充发现按同结构编号 F-1xx

产出（写入 <round目录>/02-assessment.md）：
- 逐条标注表：finding_id | 状态(accepted/rejected/modified) | 理由 | 复核证据
- 补充发现（如有）
- 对待决策清单的完善建议

硬规则：保留原 finding ID 与原文，只加标注；你的判断同样要证据。

返回：产出路径 + ≤10 行摘要（接受/拒绝/修改/新增计数 + 分歧最大的 1-2 条）。
```

模型：与初审不同家族（三方制衡）。

## 3. 修复 executor（阶段 4）

```
任务：严格按编辑规格修改文档，执行验证闸门，记录执行日志。

输入：
<round目录>/04-fix-summary.md 中的编辑规格节（已接受项）
被修改文件

规则：
- 逐条执行规格；规格与实际不符（找不到锚文本/位置内容对不上）时立即停止该条，记录"不匹配"，转下一个——禁止自行发挥替代方案
- 每条执行后运行其"验证"命令并记录实际输出
- 结构性操作（插行等）执行后必须复查联动项（合并区域、校验/条件格式/公式范围）
- 全部完成后运行 integrity_gate.sh，输出存 <round目录>/gate.md

产出（写入 <round目录>/04-fix-summary.md 的执行记录节）：
- E-xxx → 命令 → 实际输出 → 结果(成功/不匹配) 逐条记录
- 验证闸门结果汇总

返回：产出路径 + ≤10 行摘要（成功/不匹配/失败计数 + 门禁结论）。
```

模型：工具调用稳定的模型（不要求最强推理）。

## 4. 终审 reviewer（阶段 5）

```
任务：diff 审计——验证修复是否如实、完整、无回归。

输入（只读）：
<round目录>/snapshot/（修复前快照）、修复后文件、04-fix-summary.md、02-assessment.md（接受清单）

步骤：
1. 运行 diff_snapshot.py diff，得到全部差异
2. 逐块分类：应改已改（对应 finding id）/ 应改未改 / 不应改而改（回归）/ 文本外变更（格式/属性/元数据，单独列出）
3. 复测机械层：计数、范围、链接（脚本重跑）、残留属性
4. 核对声明同步：修改摘要/决策记录/修订历史中的数字与实物一致

产出（写入 <round目录>/05-post-fix-review.md）：
- 差异分类表
- 回归清单（如有，标 P0）
- 机械复测结果
- 结论：通过 / 需回阶段 4（列明项）

硬规则：0 未解释差异才算通过；"文本没变但哈希变了"必须解释（通常是格式或属性变更）。

返回：产出路径 + ≤10 行摘要（通过与否、回归数、未解释差异数）。
```

模型：与初审不同家族。

## 协调者自查（每阶段启动前）

- [ ] 任务书是否只含路径 + 要求（没贴全文）？
- [ ] 输出路径是否已明确？
- [ ] 该角色的硬规则是否在任务书里？
- [ ] 是否该先跑脚本（机械层）再启动 agent？
