# 严重度分级与决策点

每条发现必须定级。定级的目的是决定处置路径，不是渲染情绪——各级对应固定动作。

| 级别 | 定义 | 处置 | 真实样例 |
|---|---|---|---|
| **P0 错误** | 事实错误、会导致错误做法的表述、或修复轮引入的回归 | 必须修复；修复前不得交付 | 建议使用已废弃算法；新插入行跳过空行切断表格；引用链接 404 |
| **P1 不一致/缺陷** | 声明与实物不符、覆盖缺口、结构缺陷、描述与被引文档不符 | 应修复；不修须记录接受理由 | 摘要计数不符；矩阵活动无检查项；内部文档编号写错 |
| **P2 改进/待确认** | 合理但非必须的改进；口径或位置取舍 | 由人决定采纳与否 | 章节位置调整；条目归类；弱映射换挂 |
| **P3 记录即可** | 风格、体例、与原件同源的已知问题 | 记入遗留清单 | 首行缩进类格式提示；打印设置未继承 |
| **D 决策点** | 治理判断（标识、基线、语言、法规、策略） | **只能由人决定**；agent 生成决策问题 | 文档 ID 统一方向；口令策略取舍；SLA 严于行业标准 |

定级规则：

1. 拿不准时取低不取高——夸大严重度会稀释 P0 的注意力（与检查单 H 级占比过高的教训同理）。
2. "新引入"与"原有"要区分：修复轮引入的问题至少 P1（是回归就升 P0），并在终审报告单列。
3. 一条发现只定一个级别；跨维度的拆成多条，各自定级。
4. 决策点（D）不算"发现"，单独汇总进决策记录——它不是文档的错，是需要人补的判断。

## 处置状态（finding 生命周期）

```
proposed（初审提出）→ accepted / rejected / modified（复核标注 + 人确认）
→ fixed（修复完成，附 fix id）/ deferred（记录进遗留）/ decided（决策已记录）
```

状态流转必须留痕：谁改的状态、依据是什么（复核证据或人的决定），写进 02-assessment 与 03-decisions。
